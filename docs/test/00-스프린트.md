# 스프린트 1 — 결제 기능 품질 검증

| 항목 | 내용 |
|---|---|
| 기간 | 5일 (Day 1 ~ Day 5) |
| 역할 | 개발이 끝난 결제 기능을 넘겨받은 SDET |
| 목표 | **결제 기능의 출시 가능 여부를 근거와 함께 판정한다.** 개발자 테스트가 닿지 않은 곳(실제 PG 연동, 비동기 콜백, 보안, 동시성)을 검증하고, 그 검증이 CI에서 계속 돌게 한다 |
| 하지 않는 것 | 새 기능 개발. 결함은 버그 이슈로 등록하고, 수정은 간단한 것만 직접 한다 |

2. 열: `Backlog` / `Todo` / `In Progress` / `Review` / `Done`
3. 필드 추가: `Day`(Single select: 1~5), `STLC`(Single select: 분석·계획·설계·환경·실행·결함·종료)
